Retrospectiva del Proyecto LoopBook

Aprendizajes obtenidos

El desarrollo de LoopBook permitió adquirir experiencia en el trabajo colaborativo dentro de un proyecto de larga duración, donde cada integrante desempeñó un rol específico y tuvo responsabilidades definidas. Asimismo, se reforzó el aprendizaje sobre el uso de Git como herramienta de control de versiones, comprendiendo su importancia para la organización, el seguimiento de cambios y la colaboración entre los miembros del equipo.

Evolución del proyecto

Desde el Sprint 1 hasta la etapa final, el proyecto presentó una evolución gradual. Durante las primeras iteraciones surgieron dificultades relacionadas principalmente con el uso de Git y la comprensión de algunas actividades asignadas. Estas situaciones ocasionaron retrasos y complicaciones en la integración del trabajo realizado por los diferentes roles.

El Sprint 4 representó el periodo de mayor avance para el equipo. Durante esta etapa se obtuvieron mejores resultados, se consolidó una visión más clara del proyecto y se facilitó la implementación de nuevas funcionalidades y mejoras. Gracias a ello, el desarrollo logró avanzar de manera más organizada y eficiente.

Retos enfrentados

En el Sprint 5 surgieron nuevos desafíos debido a la necesidad de realizar cambios importantes en la estructura y funcionamiento de la página. La coordinación entre algunos de los roles responsables de estas modificaciones no fue completamente efectiva, lo que generó dificultades durante el proceso de implementación.

A pesar de estos inconvenientes, se lograron desarrollar las mejoras requeridas. Posteriormente, otros integrantes colaboraron en la corrección de detalles pendientes y en el refinamiento de las funcionalidades, permitiendo cumplir con los objetivos establecidos para la entrega. Tras la revisión realizada por el docente, las mejoras fueron aprobadas satisfactoriamente.

Trabajo por roles

La distribución de actividades por roles representó uno de los principales retos del proyecto. En diversas ocasiones algunas tareas no se completaron en tiempo o no alcanzaron el nivel esperado, lo que requirió apoyo adicional por parte de otros integrantes. De manera particular, el uso de Git, la gestión de ramas y los procesos de clonación fueron aspectos que generaron dificultades recurrentes durante el desarrollo.

Estado actual del proyecto

Actualmente, el proyecto presenta algunas áreas pendientes relacionadas con la documentación, específicamente dentro de la carpeta docs del repositorio. Sin embargo, en términos de funcionalidad, el sistema se encuentra estable y preparado para su liberación a la rama principal (main). Además, el repositorio puede ser clonado y ejecutado correctamente en otros equipos, permitiendo su continuidad y mantenimiento futuro.
